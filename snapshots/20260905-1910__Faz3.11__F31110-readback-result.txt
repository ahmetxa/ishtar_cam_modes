PART 1 - THE DESTRUCTIVE FAILURE
=================================
Section 2's procedure was issued EXACTLY as the document had it written:

  adb shell su -c "sed '/pref_48m_key/s|>1<|>0<|' <PREFS> > /data/local/tmp/p.xml"
  adb shell su -c "cat /data/local/tmp/p.xml > <PREFS>"

Line 1 failed:
  /system/bin/sh: syntax error: unexpected '1< '

Line 2 then ran anyway and TRUNCATED THE LIVE PREFERENCES FILE TO 0 BYTES,
because `cat T > P` truncates P before discovering T does not exist.

  <PREFS> after:  0 bytes, owner u0_a450, mode 0660, label preserved
  /data/local/tmp/p.xml:  No such file or directory

TWO DEFECTS, AND THE SECOND IS THE ONE THAT MATTERS ANYWHERE:

  1. QUOTING. A single-quoted sed expression does not survive the
     host -> adb -> device-shell -> su -c chain intact. Host-specific. This
     project already knows the route around it (push a script, run
     `su -c 'sh /data/local/tmp/x.sh'`) and the document did not use it.

  2. DESTRUCTIVE ORDERING. `cat tmp > live` truncates `live` FIRST. If the
     filter step fails for ANY reason - a quoting slip, a full filesystem, a
     typo in the key name - the preferences are gone before anything is read
     back. Independent of shell, host and this particular bug.

RECOVERY: restored from the backup taken at 19:02, four minutes earlier.
  md5 21762bdcb09f107aad2f397351cf1337, 12169 bytes, byte-identical.
  Owner, mode and SELinux label were intact throughout - the inode-preserving
  claim held even while the content was destroyed.

THE CORRECTION, now in section 2: back up FIRST, then guard the write behind
three checks before the live file is touched at all -
  GUARD 1  temp file exists and is non-empty
  GUARD 2  temp size within 8 bytes of the original
  GUARD 3  the target value is actually present in the temp file
All three were exercised this session. The guarded form ran four times in both
directions with no failure.
