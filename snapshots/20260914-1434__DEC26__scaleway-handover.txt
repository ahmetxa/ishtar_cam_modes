# Handover: Android ROM/Kernel Compilation Server Setup

## Context
I am setting up a cloud server to compile custom ROMs and up-to-date kernels for my phone. I tried Hetzner Cloud but could not rent a server more powerful than the CCX33 due to new account limits. Therefore, I switched to Scaleway.

## Decisions Made

**Provider:** Scaleway (account opened and verified; server rental is enabled). Hourly billing; Payments stop when the server is deleted.

**Instance type:** POP2-16C-64G — 16 dedicated vCPUs, 64 GB RAM, AMD EPYC, x86_64, €0.59/hour.
Selection criteria:
- The AOSP build system requires an x86_64 Linux host. At Scaleway, the letter "A" in the name indicates ARM (Ampere Altra), while "X" and the POP2 family indicate x86_64. The entire STANDARD2-A / BASIC2-A series was eliminated because they are arm64.
- Requirement for a 4 GB RAM-per-core ratio. When compiling Android 14+, each `clang` process consistently uses ~2 GB; with 16 cores, 32 GB results in an OOM (Out of Memory) error.
- The COMPUTE3-X and POP2-HC families were eliminated because they offer 2 GB/core; the MEMORY3-X and POP2-HM families (8 GB/core) were eliminated due to excessive cost.
- An alternative was identified for sessions where I will only compile kernels: the POP2-8C-32G (€0.29/hour).

**Operating System:** Ubuntu 24.04 LTS (AOSP/LineageOS documentation assumes this; the necessary 32-bit support is available in the repository). **SSH key:** ed25519 key included, passphrase saved, added to the
Scaleway account. Completed.

**Volume capacity (610 GB total, included):**
| Volume | Tier | to you | Content |
|----------|----------|----------|---------------------------------|
| Boot | 5K | 40GB | System, packages, swap |
| Source | 5K | 310GB | .repo + source product + ccache |
| Work | 15K | 260GB | out/ directory |

Rationale: The IOPS tier is defined per volume; splitting them increases
total IOPS. The source tree—read-heavy—is placed in the cheaper 5K tier,
while the `out/` directory—involving constant small-file writes—is in
the 15K tier.
Note: The provider sells in GB (decimal), while Linux reports in GiB—
310 GB results in ~288 GiB on the server. Volumes can be expanded
(hot resizing + resize2fs) but cannot be shrunk.

## Cost Notes
- IPv4 address is not included in the instance price; there is an additional hourly charge of 0.004 EUR.
- Block storage (5K tier) costs ~0.087 EUR per GB/month; the The 15K tier is more expensive.
Volume charges continue to accrue even when the server is powered off.
- If the server is deleted via the CONSOLE, attached volumes remain;
if deleted via the API, all attached volumes are deleted as well.
- Cost-saving strategy: The working volume (output/reproducible data) can be deleted
along with the server, while the source volume (source code + ccache) is retained.

## My Next Questions

build environment on Ubuntu, syncing the repo, and performing the initial build.

  AOSPA/android_build beryl core/ccache.mk lines 29-32 (the guard) and 54-58 (CC_WRAPPER/CXX_WRAPPER := $(CCACHE_EXEC)).
